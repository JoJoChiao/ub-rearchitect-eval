0. 一頁結論

  1. 素材描述的是「把兩套舊系統整個改寫」，不是「套件版本升級」。 PDF 明列前後端分離（改 Vue.js）、JBoss 換 Spring Boot、Web Forms 換 .NET 10、相依元件重構，再加上單元／整合／回歸／效能測試與「測試結果報告」〔M01–M04〕；XLSX 原始檔名就叫 Rewrite_Material〔M10〕。JoJo 在 LINE 回問 Sung Liu「具體應該就是一些套件版本升級？」〔M09〕——雙方對範疇的理解可能差很多，這是報價前第一件要問清楚的事。
  2. 30 萬以我方自己的人天單價換算，只能買 37.5 人天。 UB 公司憲章 §5.2 人天單價 NT$8,000〔K02〕；用公會的政府採購基準（程式設計師 NT$181,502／人月）換算則約 1.65 人月〔W17〕。
  3. 三種範疇情境的工作量（本報告推估，假設寫在第 4 節）：只交文件（S1）46–94 人天；文件加代表模組試做（S2）71–144 人天；照素材字面全量改寫（S3）340–741 人天。就算只交文件，也已超過 37.5 人天（1.2–2.5 倍）；全量改寫是 9–20 倍。〔X02〕
  4. 每週實體會議 13 次的隱形成本：1 人出席約佔 30 萬的 13–24%，2 人出席約佔 26–48%（中情境：1 人 NT$52,000、2 人 NT$104,000）。同樣次數改成遠端，1 人只要 NT$19,500〔X02〕。我方先例 Sanger 案線下比遠端加價 20%〔K03〕。
  5. 素材的「1,171 檔／16.8 MB」大幅高估真正要改的程式碼。 實算後只有約 30% 是自有程式碼，其餘是第三方套件（33%）、git 版控物件與 IDE 雜訊（29%）、重複檔（7%）〔X01〕。但同時盤點又不完整：靜態掃描表完全沒掃到 TMPortal 的 238 個 Java 檔；.NET 線的程式清單只列 5 個頁面，掃描表卻列了 28 筆（去重後 27 頁，見 4.2）〔X01、X02〕。對方的盤點本身不可靠，範疇會在做的過程中長大。
  6. 案子在鏈條上的位置判斷不出來。 Kyndryl 與 Goodarc 只出現在檔名，PDF 內文沒有任何公司名〔M05〕；Goodarc 查無可確認的公開資料〔W10、K09〕。程式套件名 com.aia.tw 與大量保單／佣金類別〔M06-a～c〕顯示終端客戶可能是保險業（推論，需確認）。若是保險業，依 2025-12-31 施行的保險業委外辦法，受託方再轉包（複委託）需保險公司書面同意〔W20〕。
  7. 技術上最硬的三塊：(a) Web Forms 在新版 .NET 沒有直接對應，等於重寫 UI〔W39、W22〕；(b) Java 線的 Crystal Reports 報表，SAP 查無支援 JDK 25／Jakarta 的官方說法，Java 版 SP32 主流維護 2026-12-31 結束〔W47、W48〕；(c) 現況幾乎沒有 API 層（API 層關鍵字全體只命中 15 次／3 檔），前後端分離要新建整層 API〔X01〕。
  8. 我方實績：知識庫查無 Java EE／ASP.NET Web Forms 應用現代化的交付紀錄〔K09〕；最接近的是 Sanger Apache 伺服器版本升級（議價中、未成交）〔K04〕。

本報告不替 JoJo 決定報價金額。 第 4.8 節列出 10/12 回覆對方的可行型態（選項＋建議＋理由）。
